# cmslens

[![CI](https://github.com/armilenru/cmslens/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/armilenru/cmslens/actions/workflows/ci.yml)
[![Coverage](https://img.shields.io/badge/coverage-67.0%25-yellow)](coverage.txt)
[![Go Reference](https://pkg.go.dev/badge/github.com/armilenru/cmslens.svg)](https://pkg.go.dev/github.com/armilenru/cmslens)
[![Release](https://img.shields.io/github/v/release/armilenru/cmslens)](https://github.com/armilenru/cmslens/releases)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

cmslens определяет, на какой CMS, конструкторе сайтов или веб-фреймворке
работает сайт. Он читает HTML страницы и заголовки ответа и сверяет их с
таблицей из 556 платформ. В ней WordPress, Shopify, Drupal и Webflow, а также
многие платформы, привычные для русскоязычных сайтов: 1С-Битрикс, Tilda,
MODX, InSales, NetCat, UMI.CMS, uCoz и Flexbe.

Это библиотека на Go и программа для командной строки, без зависимостей за
пределами стандартной библиотеки.

Попробовать в браузере: [armilen.ru/services/cms](https://www.armilen.ru/services/cms)
работает на cmslens.

```text
$ cmslens wordpress.org tilda.cc 1c-bitrix.ru
wordpress.org	WordPress
tilda.cc	Tilda
1c-bitrix.ru	1C-Bitrix
```

## Установка

```sh
go install github.com/armilenru/cmslens/cmd/cmslens@latest
```

Модулю нужен Go 1.24 или новее.

Готовые программы для Linux, macOS и Windows приложены к каждому
[выпуску](https://github.com/armilenru/cmslens/releases).

## Командная строка

```text
cmslens [флаги] домен...
cmslens -file page.html
```

| Флаг | Что делает |
|---|---|
| `-json` | Печатает по объекту JSON на каждый сайт вместо строки текста. |
| `-file ПУТЬ` | Определяет платформу по сохранённой странице HTML, а не по загруженному сайту. В сеть ничего не уходит, заголовки ответа не учитываются. |
| `-timeout ВРЕМЯ` | Задаёт предел времени на один сайт, например `90s` или `2m`. По умолчанию `60s`. |
| `-scraperapi-key КЛЮЧ` | Повторяет запрос через [ScraperAPI](https://www.scraperapi.com/), если сайт не пускает сканер или не отвечает ему. По умолчанию ключ берётся из `$SCRAPERAPI_KEY`. |
| `-country КОД` | Задаёт код страны для ScraperAPI, например `us` или `de`: для сайтов, которые отвечают только посетителям из своей страны. По умолчанию не задан, и страну выбирает ScraperAPI. |
| `-lang ЗНАЧЕНИЕ` | Задаёт заголовок `Accept-Language`, например `ru-RU`. По умолчанию `en-US,en;q=0.9`. |
| `-version` | Печатает версию и завершает работу. |
| `-h` | Печатает список флагов и завершает работу. |

Флаг пишется с одним дефисом или с двумя: `-json` и `--json` означают одно и
то же.

Строка текстового вывода состоит из введённого имени, табуляции и ответа:
найденные имена через `, `; `unknown`, если ни одна платформа не набрала
достаточно баллов; `blocked by an anti-bot page`, если сайт ответил кодом 403,
503 или страницей защиты от ботов и вторая попытка её не прошла; либо `error:`
и причина. С `-json` строка становится объектом:

```text
$ cmslens -json wordpress.org
{"input":"wordpress.org","result":{"status":"ok","detected":["WordPress"],"wafBehind":false,"details":{"title":"Blog Tool, Publishing Platform, and CMS \u0026#124; WordPress.org","server":"nginx","statusCode":200}}}
```

Код выхода 0, если прочитаны все сайты; 1, если хотя бы один сайт дал ошибку
или файл для `-file` не прочитан; 2, если командная строка неверна. Сайт с
ответом `unknown` или `blocked by an anti-bot page` считается прочитанным.

## Библиотека

```go
import "github.com/armilenru/cmslens"

// Загрузить сайт и определить платформу.
res, err := cmslens.Scan(ctx, "example.com", cmslens.Options{})
fmt.Println(res.Detected) // [Next.js WordPress]

// Или определить по уже загруженной странице.
names := cmslens.Detect(html, resp.Header)
```

`Scan` принимает имя сайта или адрес и загружает главную страницу этого сайта:
путь, параметры, порт и `www.` в начале отбрасываются, так что
`https://www.example.com/some/page` запрашивается как `example.com`. Имя можно
писать кириллицей или другой письменностью: `президент.рф` запрашивается как
`xn--d1abbgf6aiiy.xn--p1ai`. В результате есть поле `Status`: `ok`, если
страница прочитана, либо `cloudflare`, если сайт ответил кодом 403, 503 или
страницей защиты от ботов любого производителя и вторая попытка её не прошла.
`errors.Is(err, cmslens.ErrNoSuchHost)` отличает опечатку в имени от сайта,
который не ответил.

## Rust

В репозитории есть и крейт Rust с тем же определителем. Он переведён с пакета
Go и сверен с ним: на 2 815 страницах корпуса, которые удалось загрузить при
добавлении крейта, оба дают одни и те же ответы с теми же баллами, на живых
сайтах одни и те же строки JSON. Крейт придёт на смену модулю Go. До тех пор
образцом остаётся пакет Go, а совпадение двух таблиц проверяет тест.

```toml
[dependencies]
cmslens = { git = "https://github.com/armilenru/cmslens", rev = "<коммит>" }
```

```rust
let res = cmslens::scan("example.com", &cmslens::Options::default()).await?;
println!("{:?}", res.detected); // ["Next.js", "WordPress"]

let names = cmslens::detect(&body, &headers);
```

`scan` асинхронная, ей нужен рантайм Tokio. `detect` принимает тело как
`&[u8]`, а заголовки как `http::HeaderMap` из крейта `http` версии 1.

`cargo install --git https://github.com/armilenru/cmslens cmslens` собирает ту же
команду с теми же флагами и тем же выводом. Крейту нужен Rust 1.88 или новее.

## Как устроено определение

У каждой платформы есть признаки с весами в теле страницы (пути к файлам,
метатег generator, встроенные скрипты) и в заголовках ответа (куки,
`x-powered-by`). Заголовок весит больше разметки: подделать его труднее.
Побеждает платформа с наибольшим числом баллов, и сверху действуют три
правила:

- **У сайта один движок.** Побеждает только один движок: CMS, конструктор
  сайтов или серверный фреймворк. Слой отображения вроде Next.js, Nuxt или
  Astro показывается рядом с ним, так что сайт с отдельным фронтендом
  получает два имени, например `[Next.js WordPress]`. Первым идёт имя с
  большим числом баллов, а при равенстве движок.
- **По одному слабому признаку ответа нет.** Если набрано меньше 1 балла,
  ответа нет.
- **Короткие фрагменты ищутся с границы слова.** Иначе `evo-` найдётся внутри
  транслитерации `derevo-alyuminievaya`, и сайту припишется движок, на
  котором он не работает. Тест проверяет это для каждого признака.

Все признаки тела ищутся за один проход алгоритма Aho-Corasick, а
регулярное выражение запускается только на тех страницах, где нашлись все
его буквальные части. Новые платформы почти не меняют стоимость сканирования.

Комментарии в [`signatures.go`](signatures.go) объясняют для многих записей,
какая ложная находка на настоящем сайте определила вид признака.

## Безопасность

`Scan` рассчитан на работу на сервере с адресами, которые вводят
пользователи. Каждое соединение проходит через проверку того IP-адреса, к
которому открывается сокет, а не только имени: частные сети, петлевые адреса,
адреса локальной связи (link-local) и адрес метаданных облака
(`169.254.169.254`) запрещены на каждом перенаправлении и на каждом запасном
адресе. Ответ ограничен 5 МБ, перенаправлений не больше 5, прокси из
окружения не используются.

Если https не открылся, `Scan` пробует http. Если сайт ответил кодом 403, 503
или страницей защиты от ботов, он спрашивает ещё раз без проверки
сертификата. Поэтому ответ говорит, на чём работает сайт, но не удостоверяет,
кто отдал страницу.

## Как добавить платформу

1. Добавьте запись в `cmsSignatures` в [`signatures.go`](signatures.go).
   Признак в теле страницы пишется `` b(`...`) `` (вес 1) или
   `` bw(`...`, 0.5) ``; признак в заголовке стоит под именем заголовка
   строчными буквами и пишется `` h(`...`) `` (вес 2) или `hw`. Каждый признак
   это регулярное выражение в синтаксисе RE2 без учёта регистра, а признак
   только из букв, цифр, `_` и `-` начинается с `\b`. Лучше брать признаки,
   которые оставляет сама платформа (адрес её CDN, generator, куки), а не её
   название: его упоминают и другие сайты. При равенстве баллов побеждает
   запись, которая стоит в таблице выше.
2. Добавьте ту же запись на то же место в `CMS_SIGNATURES` в
   [`src/signatures.rs`](src/signatures.rs), по образцу соседних:
   `entry("Name", Signature { body: &[b(r"...")], ..NONE })`. Тест
   `table_matches_the_go_source` падает, пока в обеих таблицах не будут одни и
   те же признаки с теми же весами.
3. Увеличьте на единицу число записей там, где оно записано: в
   `TestAllSignaturesCompile` ([`signatures_test.go`](signatures_test.go)), в
   `all_signatures_compile`
   ([`src/tests/signatures_test.rs`](src/tests/signatures_test.rs)) и в
   первом абзаце обоих README. `plans_follow_the_features`
   ([`src/tests/match_test.rs`](src/tests/match_test.rs)) считает признаки по
   видам: при падении он печатает новые числа, и они должны сдвинуться ровно
   на добавленные признаки.
4. Если платформа это слой отображения, который работает поверх движка, как
   Next.js, добавьте её имя в `frontendLayer` в
   [`signatures.go`](signatures.go) и в `FRONTEND_LAYER` в
   [`src/signatures.rs`](src/signatures.rs).
5. Если платформа определилась на настоящем сайте неверно, добавьте урезанную
   разметку тестом в [`falsepositive_test.go`](falsepositive_test.go) и тот же
   тест с именем в snake case в
   [`src/tests/falsepositive_test.rs`](src/tests/falsepositive_test.rs).
6. Добавьте общедоступный сайт на этой платформе в
   [`testdata/corpus.tsv`](testdata/corpus.tsv): домен, табуляция и ожидаемый
   ответ. Затем проверьте всю таблицу на живых сайтах:

   ```sh
   testdata/corpus.sh /tmp/corpus
   CMSLENS_CORPUS=/tmp/corpus go test -count=1 -run TestCorpus -v .
   CMSLENS_CORPUS=/tmp/corpus cargo test corpus -- --ignored
   ```

   Скрипту нужны bash и curl. Он загружает около 2 900 общедоступных сайтов,
   примерно у 1 900 из них записан ожидаемый ответ, остальные загружаются и
   печатаются, но не сверяются. `testdata/corpus.sh /tmp/corpus example.com`
   загружает только названные сайты. Сайты отвечают по-разному в зависимости от того, откуда их спрашивают,
   поэтому часть расхождений может идти от сети, а не от таблицы.

## Как помочь

Любая правка начинается с задачи. В отчёте об ошибке сказано, что запустили,
что ожидали и что получили; так же сообщают о недостающей платформе или
функции. Pull request ссылается на свою задачу и делает одно дело, а
исправление ошибки приходит с тестом, который без него падает. В основную
ветку правки попадают только через pull request, и GitHub даёт слить его,
только когда прошли тесты Go, линтер и проверка покрытия; проверки Rust тоже
идут на каждом pull request.

Нужны Go 1.24 или новее, golangci-lint 2 (в CI v2.15.0) и Rust 1.88 или новее
с clippy и rustfmt. Перед отправкой:

```sh
go test -race ./...
golangci-lint run         # все линтеры, кроме нескольких отключённых в .golangci.yml
go run ./internal/cover   # переписывает coverage.txt и значок в обоих README
cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test
```

`coverage.txt` и оба README коммитят вместе с правкой. В `coverage.txt` число
операторов без теста в каждом файле, и CI падает, если файл в коммите
расходится с тем, что дают тесты: правка, оставившая код без теста, видна в
собственном диффе.

## Состояние

cmslens ведёт [armilen](https://github.com/armilenru), на нём работает
определитель на [armilen.ru](https://www.armilen.ru/services/cms). Версия
0.x: API библиотеки ещё может меняться при смене второго числа версии, а
правка, которая ломает вызывающий код, стоит первой в заметках к выпуску.
Выпуск делается тегом: тег `v0.2.0` запускает CI, затем собирает программы
для шести платформ и публикует их с заметками из слитых pull request.
